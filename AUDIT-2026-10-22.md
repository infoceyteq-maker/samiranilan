## 2. Security review

### 2.1 What is good

- **No secrets anywhere.** No `.env*` file, no API keys, tokens, passwords, `sk_live`,
  `AIza…` or bearer strings in the working tree or in git history (the repo has a single
  commit and no `.env` has ever been committed).
- **No XSS surface.** The only `dangerouslySetInnerHTML` is the static JSON‑LD block
  (content is hard-coded and `<` is escaped to `\u003c`). No `eval`, no `new Function`,
  no `innerHTML`, no `document.write`.
- **No user input is rendered.** The contact form only builds a `mailto:` URL from
  `encodeURIComponent(...)` values — nothing hits a server or the DOM as HTML.
- **All external links are safe.** 15/15 `target="_blank"` links carry
  `rel="noopener noreferrer"` (verified by grep).
- **Only one third-party embed:** Google Drive video previews, and they are
  *click-to-play* — nothing is loaded from Drive until the visitor presses play.
- **localStorage** holds one key (`snilan-lang` = language code), wrapped in `try/catch`.
  No tracking, no cookies, no analytics dependency.
- **Dependencies are current within their major line:** Next.js 15.5.28, React 19.3.1,
  framer-motion 11.18.2. No known *runtime* vulnerability applies to this static site.
- **Vercel production deployment** is built from `main` with `protectedSourcemaps: true`.

### 2.2 SEC‑1 — No `.gitignore` (High, fixed)

The repo contained a **file literally named `download`** whose content was meant to be
`.gitignore`:

```
node_modules
.next
out
.env*.local
.DS_Store
```

`git status` therefore reported `node_modules/` and `.next/` (≈152 MB) as untracked — one
`git add .` away from being committed, together with any future `.env` file.

**Fixed:** added a proper `.gitignore` (dependencies, build output, env files, `.vercel`,
`.DS_Store`, logs) and deleted the stray `download` file.

### 2.3 SEC‑2 — Security headers (High, fixed)

Before: `next.config.mjs` set only `reactStrictMode`, `allowedDevOrigins` and
`images.remotePatterns` — **no security headers at all**, and Next.js advertised itself
with `X-Powered-By`.

After (`next.config.mjs` → `headers()` for `/:path*`):

| Header | Value |
|---|---|
| `Content-Security-Policy` | `default-src 'self'`; scripts/styles self + inline; `img-src` + `frame-src` limited to Google Drive / googleusercontent; `object-src 'none'`; `base-uri 'self'`; `form-action 'self' mailto:`; **`frame-ancestors 'none'` in production** (clickjacking protection) |
| `X-Content-Type-Options` | `nosniff` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=(), payment=(), usb=()` |
| `Strict-Transport-Security` | `max-age=63072000; includeSubDomains` (production only) |
| `X-Powered-By` | removed (`poweredByHeader: false`) |

The dev server uses a relaxed CSP (`'unsafe-eval'`, `ws:`, `frame-ancestors *`) so HMR and
the sandboxed live-preview iframe keep working; production stays strict.

**Verified** against a real production server (`npm start`): all headers are returned on `/`.

### 2.4 SEC‑4 — Dependency advisories (Medium, documented)

`npm audit` reports **9 vulnerabilities (6 high, 3 moderate)**:

| Package | Severity | Path | Reachable at runtime? |
|---|---|---|---|
| `postcss` ≤ 8.5.22 | high | nested under `next` | No — build-time CSS processing |
| `braces`, `micromatch`, `chokidar`, `fast-glob` | high | via `tailwindcss` CLI | No — dev/build only |
| `postcss-selector-parser` | moderate | via `postcss-nested` → `tailwindcss` | No — dev/build only |

Every fix requires a **major** upgrade (`next@16`, `tailwindcss@4`) — i.e. a breaking
change. Because this site is fully static (no API routes, no server actions, no user
input), none of these can be triggered by a visitor. **Recommendation:** keep them on the
list and do the Next 16 / Tailwind 4 upgrade as a planned migration, not an emergency.

### 2.5 SEC‑5 — Vercel Hobby plan (Medium, action recommended)

The project is on the **Hobby** plan. Vercel's Fair Use / plan terms restrict Hobby to
**personal, non-commercial** projects, and this site advertises paid services. Upgrading to
**Pro** is the compliant option and also adds better deployment protection, usage limits
and team features.

### 2.6 Other observations

- **Google Drive library is public by design** — the "Open the full Drive library" link and
  every work card point at files shared as "Anyone with the link". That is intended for a
  portfolio, but anyone with the link can open all 169 files.
- **Personal phone + e‑mail are public** on the page (intended for business). Expect the
  usual spam; a contact form endpoint would reduce it.
- **No cookie banner needed** — the site sets no cookies and loads no trackers.

## 3. SEO & metadata

### 3.1 SEO‑1 — Broken social previews (High, fixed)

The deployed `app/layout.js` had **no `metadataBase`**. I reproduced the build both ways:

```
# before
<meta property="og:image" content="http://localhost:3000/images/hero-main.jpg">
⚠ metadataBase property in metadata export is not set for resolving social open graph
  or twitter images, using "http://localhost:3000".

# after
<meta property="og:image" content="https://samiranilan.vercel.app/images/hero-main.jpg">
```

So every WhatsApp / Facebook / LinkedIn / X share of the site showed **no image** (the
scraper could not fetch `localhost`). Now fixed with
`metadataBase: new URL(SITE_URL)` plus absolute canonical, `og:url`, image dimensions
(1200×630) and alt text.

### 3.2 SEO‑2 / SEO‑3 — Crawlability & rich results (Medium, fixed)

Added:
- `app/robots.js` → `/robots.txt` (allow all + sitemap)
- `app/sitemap.js` → `/sitemap.xml`
- `app/icon.svg` → favicon (the site previously returned 404 for `/favicon.ico`)
- `app/manifest.js` → `/manifest.webmanifest` (installable/PWA-ready metadata)
- `alternates.canonical`, `robots` directives with `max-image-preview: large`
- **JSON‑LD** `Person` + `WebSite` graph: name, alternate names, job title, e‑mail,
  telephone, location (LK), employer (Ceyteq) and `sameAs` → all 9 social profiles.
  This is what lets Google show the social links and knowledge-panel style result.

Title/description trimmed to sensible SERP lengths
(`S.Nilan — Digital Strategist & Founder of Ceyteq`, 49 chars; description 158 chars).

## 4. Code & build findings

### 4.1 CODE‑1 — Stale duplicate files at the repo root (High, fixed)

The repository contained **two copies of the whole source tree**:

```
/About.jsx, /Hero.jsx, /Navbar.jsx … (15 components)
/page.js, /layout.js, /data.js, /translations.js, /globals.css
/hero-main.jpg, /hero-meeting.jpg, /hero-strategy.jpg
```

Only `app/`, `components/`, `lib/` and `public/` are actually built (`@/*` → `./*`, and
`app/page.js` imports `@/components/...`). The root copies were **older**: they still
contained the removed `LIVE_WEBSITES` array (10 client websites) and the matching
`LiveWebsitesBlock`, which the live site does **not** show. Editing those root files would
have silently changed nothing — a classic “I fixed it but the site didn’t update” trap.

**Fixed:** deleted the 23 stale files (including the three root JPGs that duplicated
`public/images/`). They remain available in the `main` history if ever needed.

### 4.2 CODE‑2 — Build dependency on Google Fonts (Medium, fixed)

`next/font/google` downloads Inter and Manrope from `fonts.googleapis.com` **during the
build**. Reproduced here:

```
ECONNRESET, host: 'fonts.googleapis.com'
`next/font` error: Failed to fetch `Inter` from Google Fonts.
Build failed because of webpack errors
```

On Vercel it currently works, but a Google Fonts outage/rate-limit blocks your deploys —
and you cannot build the site offline or in a restricted network.

**Fixed:** the same two typefaces are now self-hosted with
`@fontsource-variable/inter` and `@fontsource-variable/manrope` (variable fonts, woff2,
`font-display: swap`), wired into the existing `--font-inter` / `--font-manrope` CSS
variables. Zero visual change, no external request at build or runtime, 13 woff2 chunks
emitted into the build.

### 4.3 CODE‑3 / CODE‑4 — Small correctness & a11y fixes

- Contact form: every field now has a paired (screen-reader) `<label>` and a `name`
  attribute, so password managers/autofill and assistive tech work correctly.
- Google Drive `<iframe>` now has `loading="lazy"` and a descriptive title
  (`Video: <title>`); Drive thumbnails use `decoding="async"`.

### 4.4 CODE‑5 — No ESLint configuration

`npm run lint` runs `next lint`, which in Next.js 15 has no config to read and will prompt
to create one. **Recommendation:** add `eslint` + `eslint-config-next` (dev-only) or delete
the script, so CI/lint output is meaningful.

## 5. Visual / UX

### 5.1 UX‑1 — Hero image resolution (Medium, **needs your photos**)

```
public/images/hero-main.jpg     500 × 281 px   (22 KB)
public/images/hero-meeting.jpg  612 × 408 px   (43 KB)
public/images/hero-strategy.jpg 612 × 408 px   (26 KB)
```

`hero-main.jpg` is rendered in a container up to **560 px wide** (and Next.js will generate
up to `w=3840` variants for high‑DPI phones), so the main photo is effectively upscaled
~2×. That is the single most visible quality issue on the page.

**Fix:** replace it with your own photo at **≥1600 px wide** (same 4:3–4:5 crop works
best). The two small floating cards are fine at 612 px.

### 5.2 UX‑2 — No custom 404

`/_not-found` uses the Next.js default. A branded 404 (`app/not-found.js`) with a link back
home would be a nice finishing touch.

### 5.3 UX‑3 — Language flash

The chosen language is restored in `useEffect` after hydration, so an Arabic (RTL) visitor
sees a brief English/LTR flash on each load. Acceptable for now; could be fixed with a
cookie read on the server later.

## 6. Performance snapshot (production build)

```
Route (app)                     Size   First Load JS
○ /                            15.2 kB         173 kB
○ /_not-found                    993 B         104 kB
+ First Load JS shared by all                  103 kB
```

- Static prerender of `/` — served from Vercel's edge cache (`s-maxage=31536000`).
- Fonts self-hosted, `display: swap`, only the latin subset is used by this content.
- Images optimised by `next/image`; the hero has `priority`.
- 173 kB JS is fine; the largest lever would be `framer-motion`’s `LazyMotion`
  (`m` components instead of `motion`) — optional, saves roughly 30–40 kB.
